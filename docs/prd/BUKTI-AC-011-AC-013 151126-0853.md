## 1. AC-011: parameter tak dikenal ditolak dengan namanya

**Definisi (PRD):** memanggil `Page.captureScreenshot` dengan parameter tak
dikenal mengembalikan galat yang menyebut nama parameter itu, bukan respons
sukses. **Metode:** respons CDP mentah untuk dua parameter, satu sah dan satu
karangan.

### 1.1 Bukti tingkat unit: tes merah lalu hijau

Tes `parameter_tak_dikenal_ditolak_dengan_namanya` di
`crates/cdp/tests/native_state.rs`. Penjaga `tolak_param_tak_dikenal`
dimatikan sementara untuk membuktikan tesnya benar-benar menangkap, bukan
hijau karena kebetulan.

| Keadaan penjaga | Hasil | Keluaran |
|---|---|---|
| Dimatikan (MERAH) | `0 passed; 1 failed`, exit 101 | `left: None, right: Some(-32602)` |
| Aktif (HIJAU) | `1 passed; 0 failed`, exit 0 | `test parameter_tak_dikenal_ditolak_dengan_namanya ... ok` |

Seluruh berkas tes: `28 passed; 0 failed; 0 ignored; finished in 0.57s`
(`cargo test -p cdp --test native_state --profile dev --config profile.dev.debug=0`).

### 1.2 Bukti tingkat soket: frame mentah

Dijalankan dengan `python3 ac011-raw.py` terhadap daemon hidup. Frame dikirim
apa adanya, `data` base64 dipotong supaya terbaca.


### 1.3 Cakupan penolakan

`tolak_param_tak_dikenal` dipasang di empat metode, ditambah dua penolakan
bernama yang sudah ada sebelumnya:

| Metode | Parameter didukung |
|---|---|
| `Page.navigate` | `url`, `referrer`, `transitionType`, `transitionQualifiers`, `gesture`, `frameId` |
| `Page.setDocumentContent` | `html`, `frameId` |
| `Page.captureScreenshot` | `format`, `quality`, `clip`, `captureBeyondViewport`, `optimizeForSpeed`, `fromSurface` |
| `Runtime.evaluate` | `expression`, `returnByValue`, `userGesture`, `includeCommandLineAPI`, `silent`, `contextId`, `timeout`, `awaitPromise` |

Penolakan bernama lain: `frameId` yang tidak menunjuk bingkai mana pun, dan
`awaitPromise: true` (mesin ini tidak punya `objectId`, jadi Promise tidak bisa
ditunggu di sisi protokol).

## 2. AC-013: log daemon tanpa nilai kosong

**Definisi (PRD):** tidak ada baris log berisi tanda tanya sebagai nilai,
khususnya `pss_mb=?`; setiap klaim pengukuran mandiri berisi angka atau tidak
ada sama sekali. **Metode:** `grep` atas berkas log satu sesi, hitungan nol.

### 2.1 Dua nilai kosong yang benar-benar ada di log lama

Log sesi 01:06 UTC, sebelum perbaikan:

```
INFO menyalakan mesin mesin=native kind=rust-native binary= user_data_dir=/home/adijr/.cache/...
INFO mesin siap mesin=native kind="rust-native" pid=None http=http://127.0.0.1:42989
```

- `binary=` kosong: mesin native berjalan di dalam proses daemon, jadi tidak
  punya biner. Medan itu ditulis kosong, dan pembaca log tidak bisa
  membedakannya dari kolom yang gagal diisi.
- `pid=None`: pid tidak ada untuk mesin native. Ditulis sebagai `None`, yang
  terbaca seperti pid yang gagal dibaca.

### 2.2 Perbaikan

| Berkas | Perubahan |
|---|---|
| `crates/browserd/src/daemon.rs` | `binary` hanya ditulis kalau `mesin.binary` tidak kosong; `pid` hanya ditulis kalau `Some`; `pss_mb` hanya ditulis kalau PSS benar-benar terbaca |
| `crates/engine/src/slot.rs` | `pid` pada "mesin dinyalakan ulang" hanya ditulis kalau `Some` |

Medan yang tidak terukur hilang dari baris log, bukan diisi nilai kosong.

### 2.3 Hitungan sebelum dan sesudah

Pola yang dipakai, dan kenapa:

| Pola | Arti |
|---|---|
| `=[[:space:]]+[a-zA-Z_]+=` | `=` langsung diikuti spasi lalu nama medan berikutnya: nilainya kosong |
| `=$` | `=` di akhir baris: nilai kosong |
| `=None` | medan diisi `None`, bukan angka |
| `=\?` | nilai tanda tanya, pola yang disebut PRD |
| `=""` | string kosong |

Hasil `grep -Ec` atas dua berkas log satu sesi:

| Pola | Log lama (01:06 UTC) | Log baru (01:50 UTC) |
|---|---|---|
| `=[[:space:]]+[a-zA-Z_]+=` | **1** | **0** |
| `=$` | 0 | 0 |
| `=None` | **1** | **0** |
| `=\?` | 0 | 0 |
| `=""` | 0 | 0 |

Log baru: 24 baris, satu sesi penuh dari start daemon sampai tutup tab, dengan
lalu lintas nyata di dalamnya:

| Langkah sesi | Hasil |
|---|---|
| start daemon + mesin native | `mesin siap ... http=http://127.0.0.1:38053` |
| `fetch()` dari halaman ke fixture | 8 baris `DEBUG fetch dari halaman diizinkan gerbang jaringan` |
| `Runtime.evaluate` ekspresi biasa | `{"value": 2}` |
| `Runtime.evaluate` parameter karangan | `-32602` menyebut `karangan` |
| `Page.navigate` ke host tak dikenal | `-32000 Dns Failed` |
| `Page.navigate` ke fixture | `frameId FRAME-2` |
| `Page.captureScreenshot` | 5.088 karakter base64 |
| `Target.closeTarget` | `{"success": true}` |
| sesi CDP ditutup | `INFO sesi CDP selesai to_engine=7 from_engine=6` |

### 2.4 Perintah reproduksi

```bash

RUST_LOG=info /mnt/hdd/OpenCrabs/build/cargo/debug/browserd serve \
  --config /tmp/ocb-tuntas/browserd-9290.toml --idle-reap-secs 0 \
  > /tmp/ocb-tuntas/ac013.log 2>&1 &

# 2. lalu lintas: satu sesi penuh, termasuk jalur galat
python3 /tmp/ocb-tuntas/ac013-traffic.py

# 3. periksa
sed 's/\x1b\[[0-9;]*m//g' /tmp/ocb-tuntas/ac013.log > /tmp/ocb-tuntas/ac013-bersih.log
for p in '=[[:space:]]+[a-zA-Z_]+=' '=$' '=None' '=\?' '=""'; do
  printf '%s -> %s\n' "$p" "$(grep -Ec -- "$p" /tmp/ocb-tuntas/ac013-bersih.log)"
done
```

## 3. Yang belum dibuktikan di dokumen ini

- **Nol nilai kosong ini berlaku untuk jalur yang dijalankan di sesi uji.**
  Jalur yang tidak tersentuh (mis. supervisor anggaran memulihkan mesin,
  handoff target, reap mesin menganggur) belum punya baris log di sesi ini,
  jadi belum diperiksa. Yang bisa diklaim: jalur start, fetch, evaluasi,
  navigasi, tangkapan layar, dan tutup tab bersih dari nilai kosong.
- **`pss_mb` tidak pernah muncul di sesi ini** karena mesin native tidak punya
  pid, jadi PSS-nya tidak terukur. Kode yang menulisnya (`daemon.rs`, supervisor
  anggaran) memakai `pss_mb = pss / MB` dengan angka yang sudah dibaca, bukan
  opsi, jadi pola `pss_mb=?` tidak bisa muncul dari situ. Ini dibaca dari kode,
  bukan dari log yang berisi baris itu.
- **AC-011 membuktikan empat metode yang dijaga.** Metode lain yang belum
  punya penjaga parameter tidak diperiksa di sini; itu pekerjaan NFR-005 dan
  dicatat terpisah di PRD.
