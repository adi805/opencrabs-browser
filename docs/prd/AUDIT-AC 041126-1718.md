## Temuan

### 1. Default `--port` menunjuk port produksi (sudah diperbaiki)

`crates/browserd/src/cli.rs:162-164` memberi `--port` default `9222`, yaitu port browser produksi, sementara komentar di baris di atasnya mengklaim "Sengaja 9224 saat pengembangan supaya browser produksi di 9222 tidak tersentuh". Komentar dan kode saling bertentangan.

Presedensi di `Resolved::resolve` (`crates/browserd/src/daemon.rs:938-941`): `args.bind` menang, lalu `file.daemon.bind`, lalu `127.0.0.1:{args.port}`. Jadi `browserd serve` polos tanpa flag dan tanpa berkas config akan mencoba bind **127.0.0.1:9222**.

Di host ini tertutupi karena unit systemd mengirim `--bind 127.0.0.1:9224`, tapi default-nya tetap jebakan, dan ini persis yang dimaksud AC-019. Diperbaiki di task 3 plan ini: default jadi 9224 plus test pengunci.

### 2. Routing per host belum tersambung ke daemon (AC-007)

Logika pemilihan mesin berbasis aturan host ada dan teruji unit di `crates/policy/src/select.rs`, tetapi tidak ada satu pun pemanggil di luar berkas itu. Pembuatan target selalu memakai mesin bawaan (`crates/cdp/src/targets.rs:270`). Konsekuensinya: aturan host belum pernah berpengaruh di jalur nyata, jadi AC-007 belum boleh disebut Verified.

Cara membuktikannya nanti: satu test integrasi dengan dua mesin nyata dan satu aturan host, yang memeriksa hasil `berubah`/`tidak_ada_perubahan` dari halaman (bukan dari balasan), plus log yang menyebut aturan mana yang menang.

## Yang belum terukur

Tiga hal ini sengaja tidak diklaim, karena buktinya belum ada:

1. `Gudang::pegang` (lease) belum dipanggil dari jalur produksi mana pun; perilaku lease versus reap baru terbukti di test `idle_reap.rs`.
2. TTL handoff 900 detik masih diuji dengan jam semu, belum live.
3. `loop_anggaran` belum diuji end-to-end dengan mesin nyata; yang teruji adalah keputusan per-mesin dan pencatatannya.
