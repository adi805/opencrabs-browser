# OxiBrowser capability evidence

This file records what OxiBrowser 0.28.0 **actually did** when the daemon talked
CDP to it, and what it did not. It is the only source for `TERUKUR_OXI` in
`crates/policy/src/select.rs`. Nothing here comes from the project's own claims.

## Why the measurement runs in CI

Every OxiBrowser release asset is a macOS binary. `file` on
`oxibrowser-unsigned` extracted from `v0.28.0` says "Mach-O universal binary
with 2 architectures", sha256
`ed60eef1b80455308e3bf3a24ec34029d0ed66c1508329818a6be58e470461a2`. There is no
Linux artifact, so the engine is built from crates.io
(`cargo install oxibrowser --version 0.28.0 --features browser --locked`, 722
packages, Blitz/Servo/boa/BoringSSL). That build belongs on a runner, not on the
machine this product runs on.

Workflow: `.github/workflows/oxi-probe.yml` (`workflow_dispatch`, input
`oxi_version`, ubuntu-latest, `libfontconfig1-dev libfreetype-dev
libexpat1-dev`). It installs the engine, then runs
`cargo test -p browserd --test oxi_probe --locked -- --nocapture` with
`OXI_BIN=$HOME/.cargo/bin/oxibrowser`.

through page script, so its failure cannot be explained by the
`skrip_halaman` failure. Two separate capabilities are broken.

## What the capability table now says

| Capability | Value | Basis |
|---|---|---|
| `layout` | `true` | the fixture was fetched over HTTP, the DOM was built, the `<title>` parsed, and a screenshot came out as a real PNG |
| `script` | `false` | page scripts do not execute |
| `cookies` | `true` | write then read back, same value |
| `input` | `false` | dispatched mouse events do not reach the page |

`layout: true` means "loads a page and renders it to PNG". It does not mean the
pixels were compared against a reference rendering, because they were not.

## Consequence for routing

Oxi is a real CDP endpoint with a working DOM, working cookies, and no page
script execution. Most of the web needs script, so the honest default is to keep
`chrome-headless-shell` as the engine for real work and use oxi where its
particular shape helps. `crates/policy` enforces that: a request whose `needs`
include `script` or `input` is refused up front for engine `oxi` instead of
failing halfway through a job.

## Reproducing

```bash
gh workflow run oxi-probe.yml --ref main
gh run watch
```

The probe prints `PROBE <name>: ok|GAGAL <detail>` for every check and a markdown
table between `PROBE_LAPORAN_MULAI` and `PROBE_LAPORAN_SELESAI`. Tests skip with
an explicit message when no engine binary is present, so `cargo test` on a
machine without OxiBrowser stays green.
