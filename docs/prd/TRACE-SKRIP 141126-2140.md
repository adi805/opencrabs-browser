## 5. Probe: blocker yang paling mahal

### 5.1 `window.addEventListener` → seluruh `<script>` batal

Halaman uji memasang:
```html
<script>
window.__urutan.push('inline-start:' + document.readyState);
document.addEventListener('DOMContentLoaded', function(){ window.__urutan.push('DCL'); });
window.addEventListener('load', function(){ window.__urutan.push('load'); });
</script>
```

Hasil (`skrip` di balasan `Page.navigate`):
```
dijalankan: 1, galat: ["skrip JavaScript gagal: Exception"]
```
`window.__urutan` setelah muat: `["inline-start:undefined"]`.

Artinya: perintah **sebelum** `window.addEventListener` jalan, dan perintah **sejak** baris itu sampai akhir blok tidak jalan sama sekali. Ini persis bentuk bootstrap React/Vue/Next/vanilla: satu baris `window.addEventListener` di awal, dan seluruh app mati karena satu TypeError.

### 5.2 `DOMContentLoaded` tidak pernah dikirim → init diam-diam tidak jalan

Di probe yang sama `document.addEventListener('DOMContentLoaded', …)` **tidak melempar** (bridge-nya ada), tapi `__urutan` tidak pernah mendapat `'DCL'`. Jadi pola:

```js
document.addEventListener('DOMContentLoaded', () => init());
```

tidak error, tidak jalan, dan tidak ada apa pun di `laporan` yang memberi tahu. Halaman hanya terlihat "belum siap" selamanya.

### 5.3 Pesan galat tidak bisa dipakai untuk debug

`throw new Error("uji-lempar")` dan pemanggilan fungsi yang tidak ada sama-sama menghasilkan string yang **identik**:

```
-32000  skrip gagal: skrip JavaScript gagal: Exception
```

Tanpa nama error, tanpa pesan asli, tanpa nomor baris. Seorang penulis halaman tidak bisa membedakan "kode saya salah di baris 3" dari "API yang saya pakai tidak ada di mesin ini". Untuk mesin yang mengaku proxy CDP, ini kelemahan diagnosa yang serius.

### 5.4 `awaitPromise` diabaikan, jadi hasil async tidak bisa dibaca

```
new Promise(r => setTimeout(() => r(42), 20))        (tanpa awaitPromise) → {}
new Promise(r => setTimeout(() => r(42), 20))        (awaitPromise: true) → {}
(async () => { const r = await fetch('…/data.json'); return 'HTTP ' + r.status })() → {}
```

Tiga tiga-tiganya `{}`. Jadi bukan cuma Promise tidak diselesaikan: **nilai balik fungsi async sama sekali tidak bisa dibaca lewat CDP**, apa pun flag-nya. Setiap skrip uji otomasi yang menulis `await page.evaluate(async () => …)` akan menerima `{}` dan menyimpulkan halamannya kosong.

### 5.5 `objectId` tidak ada → klien otomasi tidak bisa memegang elemen

```
DOM.resolveNode(document root nodeId=0)  → -32000 "node 0 bukan elemen"
DOM.resolveNode(elemen)                  → {"objectId":"node-<id>"}   ← string, bukan registri
Runtime.callFunctionOn(...)              → -32601 "metode ini tidak dikenal mesin native"
Runtime.getProperties(...)               → -32601 "metode ini tidak dikenal mesin native"
```

`objectId` yang dikembalikan (`state.rs:1268`) hanya label `node-<id>`, tanpa registri objek jarak jauh. Segitiga itulah dasar `page.$eval`, `elementHandle.click()`, dan `evaluateHandle` di Playwright/Puppeteer. Selama ketiganya `-32601`, klien otomasi mana pun hanya bisa `evaluate` ekspresi yang mengembalikan nilai primitif.

## 6. Bukti render: CSS benar-benar dilukis (dan dua cacat nyata)

`Page.captureScreenshot` pada halaman uji CSS (viewport 800×600, PNG 800×600 `00000320`×`00000258`, `devicePixelRatio 1`):

- PNG 7.973 byte, JPEG `quality:80` jalan (field `receipt` ada), WebP jalan (4.122 byte). Ketiga encoder tidak error.
- **Dilihat langsung** (bukan cuma ukuran file): kotak oranye `border-radius:14px` pada latar navy `#0b1020`, teks putih `Halo dari mesin native` pada ukuran yang benar. Jadi kaskade `<style>` + layout + raster memang bekerja.

Dua cacat yang **terlihat di gambar**, bukan disimpulkan:

1. **Latar `body` tidak merambat ke seluruh kanvas.** Area navy berhenti di tinggi konten (`≈y228` dari 600), sisanya putih. Di browser sungguhan latar `body` merambat ke kanvas viewport, jadi halaman gelap akan tampak gelap penuh.
2. **Teks terakhir terpotong di batas bawah area yang dilukis** (`#s` "state" menempel di tepi bawah panel navy). Ini persis jenis cacat yang bikin screenshot otomasi dituding "halaman rusak".

## 8. Temuan tambahan: smoke test `bench/cdp-smoke.mjs` membakar 10 detik tiap jalan

`bench/cdp-smoke.mjs` menunggu muat dengan:

```js
for (let i = 0; i < 100; i++) {
  const state = await send('Runtime.evaluate', { expression: 'document.readyState', returnByValue: true }, sessionId);
  if (state.result?.result?.value === 'complete') break;
  await new Promise((r) => setTimeout(r, 100));
}
```

`document.readyState` **selalu `undefined`** (§4), jadi `=== 'complete'` tidak pernah benar dan loop **selalu** menghabiskan 100 × 100 ms = **10 detik**.

Buktinya:

| Uji | Waktu |
|---|---|
| Navigasi ke halaman **lokal** (nol jaringan) | `real 0m10,996s` |
| `Page.navigate` ke halaman lokal yang sama, diukur di dalam skrip | **180 ms** |

Selisih 10,8 detik itu murni tidur. Konsekuensi: angka `13,8 detik` yang dilaporkan di `TRACE-NAVIGATE 141126-2135.md` §3 **tidak bisa dipakai sebagai latensi**. Angka yang benar untuk navigasi lokal: **±180 ms**, dan untuk `https://example.com` sisanya latensi jaringan + parse. Dokumen itu sudah dikoreksi di tempat, bukan dibiarkan.

Perbaikan yang benar bukan menaikkan batas loop: ganti penantian ke sinyal yang memang ada (`Page.loadEventFired` sudah dikirim di `state.rs:750`), atau isi `document.readyState` di jembatan supaya nilainya jujur.
