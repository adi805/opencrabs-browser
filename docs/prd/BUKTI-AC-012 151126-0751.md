# BUKTI AC-012: timer jatuh tempo tanpa pemicu klien

Diukur 15 November 2026, 07:44-07:51 WIB, pada daemon `rust-native` yang benar-
benar berjalan. Kriteria ini punya **dua arah**: merah saat pemompa dimatikan,
hijau saat pemompa dipasang. Satu arah saja tidak membedakan apa pun.

## Alat

| Hal | Nilai |
|---|---|
| Halaman uji | `/tmp/ocb-tuntas/fixture/timer.html`: `setTimeout(function(){ akar.textContent='berubah' }, 500)` di blok `<script>` |
| Skrip | `/tmp/ocb-tuntas/timer.py`, tiga pengukuran berurutan |
| Daemon | `browserd serve --engine rust-native --config /tmp/ocb-tuntas/browserd-9290.toml` (`bind 127.0.0.1:9290`) |
| Fixture server | `python3 -m http.server 8791` atas `/tmp/ocb-tuntas/fixture` |

Cara ukur: tab dibuka lewat `PUT /json/new?<url>`, lalu klien **diam tanpa satu
frame pun** selama jeda, lalu mengirim **tepat satu** `Runtime.evaluate` yang
membaca `document.getElementById('akar').textContent`. Kolom `timer` pada
respons yang sama mencatat berapa callback yang dikuras oleh evaluasi itu.

- A: jeda 120 ms (di bawah tenggat 500 ms) -> penanda harus `awal`
- B: jeda 1.200 ms (di atas tenggat) -> penanda harus `berubah`, `timer` harus `0`
- C: jeda 0 ms -> penanda harus `awal`

## Merah: pemompa dimatikan

Pemompa di `crates/cdp/src/native_wire/mod.rs:185` diubah dari
`from_millis(20)` menjadi `from_millis(3_600_000)` (satu jam), lalu `browserd`
dibangun ulang. Log: `/tmp/ocb-tuntas/ac012-MERAH.log`.

```
A          jeda= 120 ms  evaluasi_dikirim=1  penanda="awal"    timer=0
B          jeda=1200 ms  evaluasi_dikirim=1  penanda="awal"    timer=1
C          jeda=   0 ms  evaluasi_dikirim=1  penanda="awal"    timer=0

AC-012 lulus: False
```

Baris B adalah pasangan yang disebut kriteria: **penanda belum berubah, `timer`
bernilai 1**. Artinya timer tidak pernah jatuh tempo sendiri; ia hanya berjalan
karena evaluasi itu menguras antreannya, dan pengurasan itu terlihat di kolom
`timer`.

## Hijau: pemompa dipasang (20 ms)

Berkas dipulihkan dari `/tmp/ocb-tuntas/mod.rs.pompa20`
(`sha256 4bcf136f9ea82a070d11491c3d9175a9563a73193dca1e8142d839cf55d63192`,
identik dengan keadaan sebelum percobaan), `browserd` dibangun ulang, daemon
dijalankan lagi. Log: `/tmp/ocb-tuntas/ac012-HIJAU.log`.

```
A          jeda= 120 ms  evaluasi_dikirim=1  penanda="awal"    timer=0
B          jeda=1200 ms  evaluasi_dikirim=1  penanda="berubah" timer=0
C          jeda=   0 ms  evaluasi_dikirim=1  penanda="awal"    timer=0

AC-012 lulus: True
```

Baris B sekarang **penanda sudah berubah, `timer` bernilai 0**: perubahan itu
tidak mungkin disebabkan evaluasi pembaca, karena evaluasi itu menguras nol
callback. Satu-satunya yang berubah antara dua keadaan adalah interval pemompa.

## Yang dibuktikan

1. Di bawah daemon, `setTimeout(fn, 500)` yang dipasang saat muat **sudah
   berjalan** sesudah 1,2 detik halaman menganggur, tanpa klien menyentuh tab.
2. Perubahan itu bukan efek samping evaluasi: kolom `timer` pada respons yang
   sama bernilai `0`.
3. Kontrol A dan C menolak penjelasan "timer langsung jalan": pada 120 ms dan
   0 ms penanda tetap `awal`, jadi tenggat 500 ms benar-benar dihormati.

## Batas yang tetap berlaku

Pemompa hidup di **daemon** (`cdp::native_wire::NativeEngine`), bukan di
`engine`. Pemakai crate `engine` langsung yang tidak memanggil
`Isolat::kuras_timer` sendiri tetap tidak mendapat timer yang berjalan sendiri;
tes `native::js::tests::settimeout_dijalankan_saat_timer_dikuras`
(`crates/engine/src/native/js.rs:3069`) menjaga batas itu: sebelum dikuras
penanda belum berubah, sesudah dikuras berubah dan `kuras_timer` mengembalikan
`1`. Kedua keadaan sudah tercatat di `CELAH`.
